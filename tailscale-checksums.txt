# POR QUE ESTE ARQUIVO EXISTE
# Baixar o tarball e o .sha256 do MESMO servidor nao e um pin: e trust-on-first-use.
# Quem controlar (ou envenenar o caminho ate) pkgs.tailscale.com serve os dois
# coerentes entre si e a verificacao passa. O hash tem que ser controlado AQUI, no
# repositorio, revisado no PR e alterado so por commit. Em runtime o hermes-boot.sh
# consulta SOMENTE esta tabela; o sidecar remoto nao e mais fonte de verdade.
#
# REGRA: versao/arquitetura ausente desta tabela NAO e instalada. O boot mantem o
# binario anterior e segue. Nunca ha fallback silencioso para outra arquitetura.
#
# COMO ADICIONAR UMA VERSAO
#   1. curl -fsSL https://pkgs.tailscale.com/stable/tailscale_<ver>_<arch>.tgz.sha256
#   2. Conferir o valor por um segundo caminho independente (outra rede/maquina, ou
#      baixar o tarball e rodar sha256sum localmente).
#   3. Acrescentar a linha abaixo e registrar a procedencia neste cabecalho.
#
